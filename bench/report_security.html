Модель authz: токен берётся из JUGGLER_GRPC_TOKEN (fallback JUGGLER_ADMIN_TOKEN). Токен задан → mutating RPC требует Bearer. Токена нет + loopback bind → локальное управление разрешено. Токена нет + внешний bind → fail-closed: все мутации DENIED с предупреждением в лог при старте. Admin API симметрично: без токена поверхность read-only, мутации отвечают 403 «fail-closed».
Не тестировалось: аутентификация gRPC control-plane на уровне сообщений (протестирована только транспортная доступность unauthenticated h2) и HTTP/2-специфика data plane (сервер — HTTP/1.1). TLS-терминация хостового бинарника проверялась ранее (PFX, ручной режим).

В финальном образе админ-обработчик отвечает 400 на непарсящийся JSON и на пустой routes-документ — live-верифицировано (2026-09-22): {invalid json → 400 + сообщение парсера, {"routes": []} → 400 (отказ от wiping всех маршрутов одной опечаткой). Конфиг при этом не менялся в обоих случаях.
A8 — была подтверждённой уязвимостью №1, ЗАКРЫТА hardening-коммитом: при публикации gRPC на 0.0.0.0 без токена любой сосед по сети мог достучаться до update_config. Теперь mutating RPC требует Authorization: Bearer <JUGGLER_GRPC_TOKEN>; без токена при внешнем bind — fail-closed DENIED. Live-верификация: unauth → UNAUTHENTICATED 0.02 s, auth → конфиг применён. Для «локального управления» остаётся режим loopback-bind без токена (по умолчанию 127.0.0.1:50051).
