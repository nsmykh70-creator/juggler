Модель authz: токен берётся из JUGGLER_GRPC_TOKEN (fallback JUGGLER_ADMIN_TOKEN). Токен задан → mutating RPC требует Bearer. Токена нет + loopback bind → локальное управление разрешено. Токена нет + внешний bind → fail-closed: все мутации DENIED с предупреждением в лог при старте. Admin API симметрично: без токена поверхность read-only, мутации отвечают 403 «fail-closed».
Не тестировалось: аутентификация gRPC control-plane на уровне сообщений (протестирована только транспортная доступность unauthenticated h2) и HTTP/2-специфика data plane (сервер — HTTP/1.1). TLS-терминация хостового бинарника проверялась ранее (PFX, ручной режим).

Security correctness vs deployment security

Этот pass проверяет security correctness самого сервера: parser/framing (CL/TE/chunk), authz (admin/gRPC), configuration atomicity, SSRF/egress-политику на уровне конфига и резолва, устойчивость к exhaustion — с live-верификацией на пересобранном образе. Он не заменяет deployment security — модель развёртывания, которую настраивает оператор:
СлойПроверено этим pass'омЗона ответственности развёртывания
УправлениеBearer authz, fail-closed, 429-latch (per-IP)менеджмент-порты (admin/gRPC) не публиковать на 0.0.0.0 без необходимости; firewall/network-policy; global auth budget при распределённых атакующих
Сетьegress-политика upstream (loopback/link-local/metadata, resolve-time)network-level egress control; trusted-proxy/XFF-модель: какой IP видит Juggler за reverse proxy/WAF
